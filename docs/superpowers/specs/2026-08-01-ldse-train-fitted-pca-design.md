# LDSE 训练集拟合与安全转换设计

**日期：** 2026-08-01  
**状态：** 设计与文档已确认，待实施  
**范围：** LDSE 特征提取器、MCP 工具、FeatureExtractionAgent 路由与相关回归测试

## 1. 背景与根因

当前 `OAIZIB_Light_LDSE_FeatureExtractor.process_from_csv()` 会在输出目录中查找
`light_ldse_models.pkl`；若模型不存在，它会直接使用当前传入的 CSV 调用
`fit_shape_models(..., subset="train")`。

FeatureExtractionAgent 在收到“分别提取训练集和测试集 LDSE 特征”的请求时，会生成两个
独立的 `ldse_features_extraction` 调用，并为训练集和测试集分配不同输出目录。由于两个目录
起初都没有模型文件，两次调用会分别拟合 `StandardScaler` 和 `PCA`。结果是：

1. 测试集参与了数据依赖型变换的拟合，构成测试集信息泄漏；
2. 训练集和测试集位于两个不同的 PCA 坐标系中，同名 `LDSE_*_PC*` 列不再代表同一特征；
3. 轮廓点通过全局 `numpy.random` 随机采样，没有固定随机种子，结果难以复现；
4. `subset="train"` 只是打印及目录回退参数，无法阻止测试数据被当作训练数据拟合。

依据影像组学的训练集拟合原则，标准化、PCA、缺失值处理和特征选择等所有数据依赖型步骤，
必须只在训练集拟合；测试集只能应用冻结后的变换。

## 2. 目标

1. 确保 LDSE 的 `StandardScaler` 和 `PCA` 只在训练集拟合一次；
2. 使用同一组冻结模型分别转换训练集和测试集；
3. 阻止测试集或角色不明确的数据在无显式授权时自动拟合模型；
4. 让 Agent 在同时具备训练集和测试集路径时默认使用安全的成对提取流程；
5. 保留单 CSV 工具的兼容能力，但把“拟合”和“转换”变为显式操作；
6. 固定轮廓点采样随机种子，使相同输入和参数产生可复现结果；
7. 保存足够的模型元数据和运行清单，以便审计训练来源和下游复用。

## 3. 非目标

- 不改变 LDSE 的结构标签定义、边界提取算法或 PCA 特征命名规则；
- 不在本次优化中增加图像重采样、物理坐标转换或分割质量控制；
- 不改变 LASSO 的训练、调参和分类报告逻辑；
- 不自动重写现有 LDSE CSV 或历史模型文件；
- 不把测试集性能用于选择 `n_components` 或其他超参数。

## 4. 方案比较与选择

### 4.1 方案 A：新增训练/测试成对工具，并显式拆分拟合与转换（采用）

新增一个面向 Agent 的成对工具。它在一次受控调用中完成训练集拟合、训练集转换和测试集转换，
同时保留受约束的单 CSV 工具。该方案最难被错误编排，能清晰输出两个特征路径和共享模型路径。

### 4.2 方案 B：只给旧工具增加 `model_path`

训练调用保存模型，测试调用传入模型路径。改动较小，但依赖 Agent 正确安排调用顺序、保存并传递
上一步路径；一旦参数遗漏，仍可能产生泄漏或运行失败。

### 4.3 方案 C：删除旧工具，只保留成对提取

安全边界最简单，但会破坏只处理训练集、复用历史模型或外部脚本直接调用旧工具的场景。

综合安全性和兼容性，采用方案 A。

## 5. 核心接口设计

### 5.1 提取器职责拆分

`OAIZIB_Light_LDSE_FeatureExtractor` 调整为以下显式生命周期：

- `fit_shape_models(train_csv_path)`：只负责从训练 CSV 拟合 scaler/PCA 并保存模型；
- `load_shape_models(model_path)`：加载并校验已有模型；
- `transform_from_csv(csv_path, save=True)`：只使用内存中已加载/已拟合的模型生成特征；
- `process_from_csv(...)`：保留为兼容入口，但必须显式声明 `mode="fit_transform"` 或
  `mode="transform"`。转换模式必须提供模型，不能因模型缺失而自动拟合。

内部增加模型就绪检查。若 `pca_models` 或 `scalers` 为空，转换入口立即抛出清晰异常，不读取数据后
再静默降级为拟合。

### 5.2 成对 MCP 工具

新增：

```text
ldse_train_test_features_extraction(
    output_dir,
    train_csv_path,
    test_csv_path,
    n_components=50,
    random_seed=42,
)
```

执行顺序固定为：

```text
训练 CSV
  -> 拟合训练集 scaler/PCA
  -> 保存共享模型
  -> 转换训练集
  -> 转换测试集（同一模型）
  -> 校验两套特征列
  -> 写入运行清单
```

输出布局：

```text
<output_dir>/
  model/light_ldse_models.pkl
  train/ldse_features_summary.csv
  train/ldse_features_summary.pkl
  test/ldse_features_summary.csv
  test/ldse_features_summary.pkl
  ldse_run_manifest.json
```

工具返回结构化结果，至少包含：

- `train_features_path`
- `test_features_path`
- `model_path`
- `manifest_path`

### 5.3 单 CSV MCP 工具兼容策略

保留 `ldse_features_extraction`，增加显式参数：

- `mode`：仅允许 `fit_transform` 或 `transform`；
- `model_path`：转换模式必填；拟合转换模式不使用外部模型；
- `dataset_role`：拟合转换模式必须为 `train`；
- `random_seed`：默认 42。

安全规则：

1. `mode="fit_transform"` 且 `dataset_role!="train"` 时拒绝执行；
2. `mode="transform"` 且模型不存在时拒绝执行；
3. 不再通过输出目录是否已有模型来猜测用户意图；
4. 不再在 `process_from_csv()` 中隐式调用 `fit_shape_models()`。

旧的仅含三个参数的调用不再隐式拟合。Agent 的默认路径会切换到成对工具；外部调用者需要明确
选择训练拟合或已有模型转换。这是一项有意的安全收紧。

## 6. 模型工件与可复现性

构造器增加 `random_seed=42`。每次边界点采样使用由“全局种子＋规范化 mask 标识＋结构标签”
派生的稳定子种子，避免依赖全局随机状态或调用顺序。这样，同一病例既不会因为先处理了多少其他
病例而改变采样结果，也能在成对运行和单独加载模型转换时得到一致结果。

模型文件除现有 `pca`、`scalers` 和 `structures` 外，增加：

- `artifact_version`
- `n_components_requested`
- 每个结构实际采用的主成分数
- `random_seed`
- `fitted_dataset_role="train"`
- 训练 CSV 的规范化路径
- 训练 CSV 内容摘要（SHA-256）
- 特征列清单

`ldse_run_manifest.json` 记录输入路径、输出路径、病例数量、随机种子、请求/实际主成分数、模型路径
以及列一致性校验结果。清单不记录测试集统计量，不参与模型拟合。

## 7. 特征列一致性

不同结构可能因有效训练样本数不足而没有 PCA 模型，或者实际主成分数小于请求值。因此最终列模式
必须由训练阶段确定，而不能由测试集观察结果决定。

训练转换完成后生成训练特征列清单。测试转换必须重排到同一顺序：

- 测试集缺失的已定义 LDSE 列保留为空值，后续由现有质量检查明确报告；
- 测试集中不得产生训练模型未定义的额外 LDSE 列；
- `CaseID` 位于首列，`KLGrade` 作为标签列保留；
- 成对工具在返回前断言训练/测试数值特征列名称和顺序一致。

这里的空值策略只保证模式一致，不在测试集上拟合插补器，也不静默填零。

## 8. Agent 路由设计

FeatureExtractionAgent 的工具说明和示例更新为：

- 同时存在训练集、测试集且请求 LDSE：调用一次
  `ldse_train_test_features_extraction`；
- 只有训练集且请求建立 LDSE 模型：调用单 CSV 工具的 `fit_transform` 模式；
- 只有待转换数据时：必须同时取得已有 `model_path`，否则向用户报告缺失条件；
- MEAS 的训练/测试配对修复逻辑保持现状。

`_ensure_paired_feature_extractions()` 不再把单个 LDSE 调用克隆成两个独立调用。若上下文中同时存在
训练和测试 CSV，它会把 LDSE 计划规范化为一个成对调用；该安全网不改变 MEAS 的行为。

分类 Agent 仍从工具结果中读取两个 `ldse_features_summary.csv` 路径。必要时扩展路径收集逻辑，使
`train/` 和 `test/` 子目录能够被可靠识别为对应角色。

## 9. 错误处理

- 训练或测试 CSV 不存在：在读取前报出具体路径；
- 缺少 `CaseID`、`MaskPath` 或必要标签列：报告缺失列；
- 训练集中没有足够数据拟合任何结构：不生成可误用的空模型，整体失败；
- 模型元数据不是由训练集拟合：转换默认拒绝；
- 模型文件损坏、版本不支持或结构/缩放器不配对：加载时失败；
- 测试转换不得因任何“模型缺失”错误回退到拟合；
- 训练/测试特征列不一致：工具失败并在错误信息中列出缺失或额外列；
- 单个病例文件缺失时延续现有跳过语义，但在运行清单中记录跳过数量。

## 10. 测试设计

遵循测试先行，先写会暴露当前泄漏行为的回归测试，再修改实现。

### 10.1 提取器单元测试

1. `transform_from_csv()` 在未加载模型时抛出异常，且不会调用拟合方法；
2. `fit_shape_models()` 保存带训练角色和随机种子的模型元数据；
3. 加载训练模型后转换测试 CSV，不会再次调用 scaler/PCA 的 `fit`；
4. 相同随机种子对同一掩码返回相同的边界点采样结果；
5. 单 CSV 的测试角色不能使用 `fit_transform`。

测试优先使用小型数组、替身对象和临时 CSV，避免依赖真实 MRI 数据。

### 10.2 成对工具测试

1. 拟合方法只调用一次，且输入是训练 CSV；
2. 训练和测试转换复用同一模型实例/工件；
3. 返回的四个路径存在且分别指向正确工件；
4. 训练、测试数值特征列名称与顺序一致；
5. 运行清单明确标记 `fitted_dataset_role` 为 `train`。

### 10.3 Agent 回归测试

1. 原先“补齐第二个 LDSE 调用”的测试改为断言生成一个成对调用；
2. 成对调用使用上下文中的真实训练和测试 CSV 路径；
3. MEAS 的双调用修复行为不受影响；
4. 仅有训练 CSV 时生成显式 `fit_transform/train` 调用；
5. 分类路径选择能识别新布局中的训练和测试特征文件。

### 10.4 回归范围

运行 LDSE、Agent 计划修复、特征路径解析和分类路径作用域测试，再运行当前环境能够收集的完整测试集。
若 `SimpleITK` 或 LangChain 依赖缺失导致完整测试集无法收集，应单独报告环境限制，不把它描述为
业务测试通过。

## 11. 验收标准

1. 成对提取过程中 scaler/PCA 只对训练数据调用 `fit`；
2. 测试数据只调用冻结模型的 `transform`；
3. 新生成的训练和测试 LDSE 文件处于同一特征空间，列名和顺序完全一致；
4. 任何测试集自动拟合尝试都会得到明确错误；
5. 同一随机种子、输入和模型产生可重复结果；
6. Agent 对训练/测试 LDSE 请求只产生一个安全的成对调用；
7. 旧单 CSV 工具仍支持显式训练拟合和已有模型转换；
8. 模型和运行清单足以确认模型仅由训练集拟合；
9. 新增回归测试先失败、实现后通过，相关既有测试无回归。

## 12. 风险与后续优化

- 安全收紧会让未显式传入模式的外部旧调用失败，需要通过清晰错误信息和文档引导迁移；
- 固定采样解决可复现性，但当前 LDSE 仍使用体素坐标，尚未处理不同 spacing/orientation 带来的形状偏差；
- 轮廓点不足时可能产生缺失特征，本次只保证列模式与可审计性，后续应增加分割/样本可用性 QC；
- `n_components` 当前按训练样本数自动截断，后续若需要比较模型，应把维度选择放入训练集内部交叉验证；
- 完成本项后，下一优先级建议审计 LDSE 的物理空间标准化与固定长度轮廓表示。
